# 帮助中心搜索体验优化 PRD

## 1. 背景与问题

帮助中心当前按文章标题和后台标签匹配，不进行语义理解。用户反馈显示，使用“开发票”“改手机号”等口语词时可能无法命中正式文章标题。当前没有查询词日志，因此不能把反馈样本外推为全部用户的无结果率。

## 2. 产品目标

在不引入语义检索和智能问答的前提下，通过可维护的关键词别名配置，提升高频口语词到现有帮助文章的可达性。

## 3. 非目标

- 本期不做语义检索。
- 本期不做智能问答。
- 本期不建设查询词日志和生产量化指标系统。
- 本期不改变帮助文章内容生产流程。

## 4. 目标用户与场景

### 4.1 搜索用户

用户使用日常口语词查找帮助文章，例如输入“开发票”，期望找到“申请电子发票”相关内容。

### 4.2 内容运营

运营识别高频口语词，为其配置对应的正式搜索词，并在产品定义的规则下维护启用状态。

## 5. 本期范围

### 5.1 In Scope

- 关键词别名的新增、启用和停用。
- 将已启用别名映射到现有文章标题或标签搜索词。
- 用户搜索时沿用现有标题和标签检索及无结果页行为。
- 运营维护、产品定义规则并审核别名变更。

### 5.2 Out of Scope

- 语义检索、智能问答和自动生成答案。
- 根据用户意图自动发现或生成别名。
- 查询词日志和生产搜索指标建设。

## 6. 核心流程

1. 用户提交搜索词。
2. 系统检查是否存在已启用的关键词别名。
3. 若存在，使用对应正式搜索词继续现有标题和标签搜索；不存在则直接沿用原搜索词。
4. 返回现有搜索结果或无结果页。
5. 运营在后台维护别名，产品按照规则审核变更。

## 7. 已确认决策与待办

- 方案：采用关键词别名配置。
- 范围：本期不做语义检索和智能问答。
- 责任：运营维护，产品定义规则并审核。
- 验证：上线前使用典型查询集验证，生产量化指标待查询词日志能力具备后补充。
- 待补充：典型查询集的具体条目和维护时间由产品与运营在开发前确认。
