# 帮助中心搜索体验优化 PRD

## 1. 背景与问题

帮助中心当前按文章标题和后台标签匹配，不进行语义理解。用户反馈显示，使用“开发票”“改手机号”等口语词时可能无法命中正式文章标题。当前没有查询词日志，因此不能把反馈样本外推为全部用户的无结果率。

## 2. 产品目标

在不引入语义检索和智能问答的前提下，通过可维护的关键词别名配置，提升高频口语词到现有帮助文章的可达性。

## 3. 非目标

- 本期不做语义检索、智能问答和查询词日志建设。
- 本期不改变帮助文章内容生产流程。

## 4. 目标用户与场景

- 搜索用户输入口语词，期望找到对应帮助文章。
- 运营维护高频口语词与正式搜索词的映射关系。

## 5. 本期范围与核心流程

- In Scope：关键词别名新增、启用、停用；启用后映射到现有文章标题或标签搜索词；沿用现有结果页和无结果页。
- Out of Scope：语义检索、智能问答、自动发现别名、查询词日志建设。
- 流程：用户提交搜索词 → 检查已启用别名 → 有别名则替换为正式搜索词 → 执行现有标题/标签检索 → 返回结果或无结果页。

## 6. 功能规则

### 6.1 别名配置

- 运营可以新增、启用和停用关键词别名。
- 每条别名必须指向一个已有的正式搜索词或文章标题/标签。
- 产品定义命名、启停和审核规则，并审核运营提交的变更。
- 目标文章下线或目标标签删除后，系统自动停用相关别名并记录停用原因。
- 自动停用的别名由产品审核目标恢复情况后重新启用，运营不能直接绕过审核。
- 停用后不再参与搜索词替换，原搜索词继续走现有检索。
- 本期不根据用户输入自动生成别名或进行语义推断。

### 6.2 搜索处理

- 仅对已启用且精确匹配的别名执行替换。
- 没有匹配别名时保持原搜索逻辑和结果页行为。
- 别名命中不改变文章内容，也不引入答案生成。

## 7. 角色与权限

| 角色 | 权限 |
|---|---|
| 运营 | 新增、编辑、提交启用或停用别名；查看自动停用原因 |
| 产品 | 定义规则、审核变更、审核自动停用别名的重新启用、处理争议 |
| 普通用户 | 使用搜索，不配置别名 |

## 8. 边界与异常

- 目标正式搜索词不存在时，配置不能进入启用状态；具体提示文案待评审时确认。
- 已启用别名的目标文章下线或标签删除时，系统自动停用该别名并向运营展示目标失效原因。
- 目标恢复后保持停用，必须由产品审核后重新启用。
- 已停用别名的搜索请求按原词执行。
- 语义相近但未配置的词不自动映射。
- 别名冲突和一词多目标的处理规则需要在开发前由产品补充。

## 9. 依赖与效果验证

- 依赖现有标题和标签检索能力、内容失效事件，以及可供运营选择的正式搜索词或文章标签。
- 上线前使用产品与运营共同维护的典型查询集验证已配置别名的命中结果。
- 当前没有查询词日志，生产无结果率和搜索转化率暂不作为本期量化承诺；日志能力具备后再补充指标。

## 10. 验收标准

1. Given 已启用“开发票”→“申请电子发票”别名，When 用户搜索“开发票”，Then 系统按“申请电子发票”执行现有标题/标签检索。
2. Given 已启用别名的目标文章下线，When 系统收到内容失效事件，Then 自动停用该别名并记录目标失效原因。
3. Given 自动停用别名的目标已经恢复，When 运营尝试直接启用，Then 系统要求产品审核，审核通过后才重新启用。
4. Given 别名已停用，When 用户搜索原口语词，Then 系统不执行该别名替换并沿用原搜索逻辑。
5. Given 查询词没有已启用别名，When 用户搜索该词，Then 系统行为与现有检索一致。
6. Given 典型查询集已准备，When 执行上线前验证，Then 每条已配置别名都有可记录的预期目标词和实际搜索结果。
7. Given 本期范围，When 用户搜索任何词，Then 系统不生成智能问答或语义检索结果。

## 11. 发布前待办

- 产品与运营确认典型查询集条目和维护时间。
- 技术确认现有内容系统能够提供文章下线和标签删除事件。
- 产品补充别名冲突和一词多目标处理规则。
