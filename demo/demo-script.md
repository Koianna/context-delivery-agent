# 演示脚本

> 版本：0.1.0

## 演示环境

- 任意外部 Agent 宿主
- External Agent Gateway（或参考 CLI 适配器）
- 项目：帮助中心搜索体验优化

外部 Agent 只负责与产品经理对话、展示结果和转发确认；所有业务编排、状态转移、Skill 执行、Harness 校验和产物写入均由项目 Runtime 完成。

## 启动 Gateway

```bash
npm run gateway
```

以 JSONL 发送请求。需要继续时，只替换 `message`，保留 `task_id`，把用户的自然语言确认原文发送给 Gateway。

## 日常项目演示：用户反馈整理

将会议记录、用户反馈等材料放入项目目录后，通过外部 Agent 发送：

```text
请收集整理这些用户反馈，保留原话和不确定性，不要直接写 PRD。
```

如果材料中有“用户原话：手机号不用了”，Runtime 应保留原话、分类为用户反馈，并提出“用户是想修改手机号、解绑手机号，还是其他操作？”等待确认问题，不应直接产出“修改手机号需求”。

## 面试案例演示

面试时显式选择帮助中心搜索案例：

```bash
AGENT_PROVIDER=case npm run gateway
```

## 演示一：只整理 Context

1. 上传会议记录和用户反馈
2. Agent 分类、标注、检查冲突
3. 人工确认 Context 更新
4. 查看最终 Context 索引

## 演示二：Context → PRD

1. 基于已有 Context 开始 PRD 准备
2. 写前对齐：背景卡 + 决策账本
3. 人工确认关键决策
4. PRD 主体生成 → 确认
5. PRD 细节补充 → 审核 → 交付

## 演示三：修改与重规划

1. 修改需求范围
2. Agent 分析影响范围
3. 展示受影响和保留内容
4. 人工确认新计划
5. 返回正确节点继续
# 自然语言交互演示脚本

## 参考 CLI 启动

```bash
npm run agent
```

以下内容均在同一个会话中直接输入，不执行状态机或 Skill 脚本。CLI 只是 Gateway 的本地参考适配器。

## 路径一：材料整理到 PRD 交付

```text
只整理帮助中心搜索材料，不写 PRD
```

观察点：Agent 自动登记和分析材料，在 CP-C01 停止；界面展示两条稳定 Context 变更和一个仍待确认问题。

```text
确认全部
继续准备 PRD
按建议确认，可以生成 PRD
确认范围和核心流程
接受 P2 并交付
```

观察点：

- CP-P01 前没有 PRD 文件。
- CP-P01 后只生成 CORE。
- CP-P02 后才补充 DETAILS 并独立审核。
- CP-P03 后才标记为 delivered。
- 最终响应给出材料报告、决策账本、PRD 和审核报告的位置。

## 路径二：修改与重规划

```text
修改已交付需求：目标文章下线或目标标签删除后，系统自动停用相关别名并展示原因，产品审核后可重新启用
```

观察点：Agent 先创建不可变快照，再给出影响范围、保留范围和最小重规划，在 CP-R01 停止，不直接覆盖 PRD。

```text
批准重规划
```

观察点：任务只返回 PRD 细节修订节点，目标、范围、核心流程和已确认决策保持不变。
