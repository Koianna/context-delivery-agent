# PRD 写作错误示例

> **目的**：通过负面示例，明确展示"五不"清单中禁止的写法。

---

## 错误类型 1：写技术实现

### ❌ 错误示例

```markdown
## 功能需求：攻击树节点手动添加

### 技术方案
- 后端使用 Python Flask 框架实现 RESTful API
- 数据库使用 PostgreSQL 存储节点数据
- 前端调用 `/api/attack-tree/nodes` POST 接口
- 接口参数：
  ```json
  {
    "node_name": "string",
    "parent_id": "uuid",
    "node_type": "threat|vulnerability"
  }
  ```
- 使用 Redis 缓存节点树结构，TTL 设置为 300 秒
- 后端架构采用 MCP 工具模式，通过 Tool Calling 实现
- Temperature 设置为 0.7，MaxTokens 设置为 2000
```

### ✅ 正确写法

```markdown
## 功能需求：攻击树节点手动添加

### 功能描述
- 用户可以在攻击树中手动添加新节点
- 节点需要指定名称、父节点、类型（威胁/漏洞）
- 添加后，节点立即显示在攻击树中
- 节点数据需要持久化存储
```

**原则**：PRD 描述"做什么"，不描述"怎么做"。技术栈、API 设计、数据库选型、架构模式、配置参数都属于技术实现细节。

## 错误类型 2：写设计参数

### ❌ 错误示例

```markdown
## 功能需求：删除节点确认

### 交互设计
- 用户点击删除按钮后，弹出确认对话框
- 对话框宽度：480px，高度：240px
- 标题文字：16pt，#333333，Inter 字体，行高 24px
- 确认按钮：120px × 40px，圆角 4px，背景色 #FF4444，悬浮时 #FF2222
- 取消按钮：120px × 40px，圆角 4px，边框 1px solid #DDDDDD
- 按钮间距：16px
- 对话框阴影：0 4px 12px rgba(0, 0, 0, 0.15)
```

### ✅ 正确写法

```markdown
## 功能需求：删除节点确认

### 交互设计
- 用户点击删除按钮后，弹出确认对话框
- 对话框标题："确认删除节点"
- 对话框内容："删除后无法恢复，确认删除该节点吗？"
- 提供两个操作按钮：
  - "确认删除"（破坏性操作，需醒目提示）
  - "取消"（次要操作）
```

**原则**：PRD 使用功能性描述，不定义像素、色号、字体。视觉设计由设计师根据设计系统完成。

## 错误类型 3：写 Skill / 代码层内容

### ❌ 错误示例

```markdown
## 功能需求：AI 辅助生成攻击树

### 实现方案
- 修改 `attack-tree-generation` Skill
- 在 Skill 的 `prompt.md` 中增加节点生成规则
- Skill 通过 Tool Calling 调用 `node-validator` 工具
- 实现代码示例：
  ```python
  def generate_nodes(context):
      skill_runtime = SkillRuntime.load("attack-tree-generation")
      result = skill_runtime.execute(context)
      return result.nodes
  ```
- Agent 需要使用 ReAct 循环模式
- 配置两层 LLM：主 LLM 负责规划，子 LLM 负责生成
```

### ✅ 正确写法

```markdown
## 功能需求：AI 辅助生成攻击树

### 功能描述
- 系统根据用户输入的安全目标，自动生成初步的攻击树结构
- 生成的节点需要包含：节点名称、节点类型、风险等级
- 生成结果提供给用户，用户可以编辑、删除或补充节点
- 生成过程需要可观察（显示进度或状态）
```

**原则**：PRD 描述产品能力，不描述 Skill 名称、代码实现、Agent 架构。Skill 是技术代码的一种，属于研发决策范畴。

## 错误类型 4：写废话

### ❌ 错误示例

```markdown
## 产品背景

在当今数字化转型的大背景下，网络安全已经成为企业发展的重要基石。随着云计算、大数据、人工智能等新技术的蓬勃发展，网络安全威胁也日益复杂多变。攻击树作为一种有效的威胁分析工具，能够帮助企业全面识别、评估和管理网络安全风险，为企业的数字化转型保驾护航。

本次功能升级旨在为用户提供更加便捷、高效、智能的攻击树管理体验，通过创新的产品设计和先进的技术架构，打造业界领先的网络安全分析平台，助力企业在激烈的市场竞争中立于不败之地。我们相信，通过不断的产品迭代和优化，一定能够为用户创造卓越的价值，实现企业与用户的共赢发展。
```

### ✅ 正确写法

```markdown
## 产品背景

当前问题：
- 用户创建攻击树时，只能通过自动分析生成，无法针对特定场景手动补充节点
- 实际使用中，自动分析可能遗漏某些已知威胁，需要人工干预

本次目标：
- 支持用户手动添加攻击树节点，补充自动分析的不足
- 提高攻击树的完整性和准确性
```

**原则**：避免营销话术和冗长段落。多用要点（Bullet points）、表格和清晰的逻辑流。

## 错误类型 5：设限（过度约束）

### ❌ 错误示例

```markdown
## 功能需求：节点添加

### 约束条件
- 节点名称必须严格遵循格式："[类型]-[序号]-[描述]"
  - 示例："TH-001-SQL注入攻击"
  - 类型只能是：TH（威胁）或 VU（漏洞）
  - 序号必须是 3 位数字，从 001 开始
- 节点层级不超过 5 层（硬性限制）
- 节点数量单棵树不超过 100 个（硬性限制）
- 节点描述只能使用中文，不能包含英文或数字
- 节点图标必须从预定义的 20 个图标中选择，不支持自定义
```

### ✅ 正确写法

```markdown
## 功能需求：节点添加

### 约束条件
- 节点名称限制 50 字符（与其他元素名称限制一致）
- 建议节点层级不超过 5 层（深度过大影响可读性，但不强制限制）
- 单棵树节点数量建议控制在 100 个以内（性能考虑，超过时提示用户）
- 节点描述支持中英文混合输入
- 节点图标提供默认图标库，后续版本考虑支持自定义上传
```

**原则**：除非必要，不要人为限制产品的灵活性。必要的限制要说明原因（性能/安全/业务规则），非必要的限制改为"建议"而非"硬性限制"。

## 综合错误示例

### ❌ 完整的错误 PRD

```markdown
# PRD：攻击树节点手动添加功能 v1.0

## 技术架构
后端使用 Python Flask + PostgreSQL + Redis，前端使用 React 18 + TypeScript。通过 MCP 工具实现 Agent 能力，使用 ReAct 循环模式。

## 功能需求

### 1. 添加节点对话框
- 宽度 600px，高度 400px，背景色 #FFFFFF
- 标题：24pt Inter Bold，颜色 #1A1A1A
- 输入框边框：1px solid #E0E0E0，圆角 8px
- 确认按钮：120px × 48px，背景色 #0066FF，悬浮时 #0052CC

### 2. 后端实现
- 修改 `node-manager` Skill 的 prompt.md
- 增加 POST /api/v1/attack-tree/nodes 接口
- 参数校验使用 Pydantic 模型
- 数据写入 PostgreSQL 的 attack_tree_nodes 表
- Temperature 设置为 0.5

### 3. 约束条件
- 节点名称格式：[TH/VU]-[001-999]-[描述]（强制）
- 节点层级不超过 3 层（硬性限制）
- 节点数量不超过 50 个（硬性限制）
- 只能添加中文节点名称

## 产品愿景
打造业界领先的网络安全分析平台，为企业数字化转型保驾护航，实现卓越的用户体验和商业价值。
```

### ✅ 正确的 PRD

```markdown
# PRD：攻击树节点手动添加功能 v1.0

## 产品背景

当前问题：
- 自动分析生成的攻击树可能遗漏已知威胁
- 用户无法针对特定场景补充节点

本次目标：
- 支持手动添加节点，补充自动分析不足
- 提高攻击树的完整性

明确不做（v1.0）：
- 批量导入节点（使用频率低）
- 从其他项目复制节点（跨项目依赖复杂）

## 核心流程

1. 用户在攻击树中点击"添加节点"
2. 弹出对话框，输入：
   - 节点名称（必填，50 字符以内）
   - 父节点（必填，从现有节点选择）
   - 节点类型（必填，威胁/漏洞）
3. 点击"保存"
4. 节点立即显示在攻击树中

## 功能需求

### 添加节点对话框
- 标题："添加节点"
- 字段：
  - 节点名称（文本输入，50 字符限制）
  - 父节点（下拉选择，显示现有节点列表）
  - 节点类型（单选，威胁/漏洞）
- 操作按钮：
  - "保存"（主要操作）
  - "取消"（次要操作）

### 约束与异常
- 节点名称不能为空
- 节点名称不能与同级节点重复
- 父节点不能选择自己（防止循环）
- 保存失败时显示错误提示
```

## 总结：五不清单检查点

写完 PRD 后，逐项检查：

| 检查项 | 自查问题 |
|--------|---------|
| ✅ 不写技术实现 | PRD 中是否出现：技术栈、API 接口、数据库表、配置参数？ |
| ✅ 不写设计参数 | PRD 中是否出现：像素、色号、字体大小、具体间距？ |
| ✅ 不写 Skill/代码 | PRD 中是否出现：Skill 名称、代码片段、Agent 架构？ |
| ✅ 不写废话 | PRD 是否有营销话术、冗长段落？是否可以改为要点？ |
| ✅ 不设限 | PRD 是否有过多硬性限制？是否说明了限制原因？ |

**如果任一项答案为"是" → 违反五不清单，需要修改。**
