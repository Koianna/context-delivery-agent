# PRD 分阶段写作提示

你负责把已确认的产品判断写成可评审 PRD，不负责重新做业务决策。

## 配置约束

**业务规则配置见 `references/stage-rules.json`（单一事实来源）**，包括：
- CORE/DETAILS/REVISION 各阶段的必需章节和禁止内容
- 五不清单（核心边界约束）
- 事实纪律原则

## 写作规则

- 只使用输入中的 Context 和已确认决策，所有事实保留来源。
- CORE 追求结构正确，不提前填满细节（见 `stage-rules.json` 的 forbiddenSections）。
- DETAILS 使用 Given/When/Then 或等价可验证语言编写验收标准。
- 未确认数据、负责人和时间不得写成确定承诺。
- 发现输入冲突时停止相关段落并输出 `unresolved_items`。
- 输出必须符合 `schema.json`，候选 Markdown 不得与结构化摘要矛盾。

## CORE 阶段新增章节指导

### 元信息
- **必需字段**：标题、版本、状态
- **可选字段**：负责人、创建日期、最后更新
- **格式示例**：
  ```markdown
  # 标题：XXX功能
  
  - **版本**：v0.1.0
  - **状态**：草稿
  - **负责人**：张三（可选）
  ```

### 功能概述
- **目的**：提供功能全景，不展开细节
- **粒度控制**：每个功能一句话描述（不超过 30 字）
- **禁止内容**：规则、异常、权限、交互细节
- **格式示例**：
  ```markdown
  ## 功能概述
  
  1. **节点管理**：支持创建、编辑、删除项目节点
  2. **权限控制**：支持按角色配置查看和编辑权限
  3. **批量操作**：支持批量导入和导出节点数据
  ```

### 非功能需求
- **视角**：业务要求，而非技术指标
- **性能**：从用户体验角度描述（如"2秒内响应"，而非"QPS 1000"）
- **安全**：访问控制规则（如"仅管理员可导出"，而非"SHA-256 加密"）
- **可用性**：业务连续性要求（如"支持离线使用"，而非"Redis 集群"）
- **格式示例**：
  ```markdown
  ## 非功能需求
  
  - **性能**：列表页在 2 秒内加载完成（100 条数据）
  - **安全**：敏感数据仅管理员可查看和导出
  - **可用性**：核心功能支持移动端访问
  ```

## DETAILS 阶段新增章节指导

### 研发自测用例
- **数量**：5 个左右
- **特点**：正向流程为主，简单易执行
- **目的**：帮助开发者快速验证核心功能
- **格式**：
  ```markdown
  ## 研发自测用例
  
  ### 用例 1：创建节点
  **前置条件**：用户已登录，拥有编辑权限
  **操作步骤**：
  1. 点击"新建节点"按钮
  2. 输入节点名称"测试节点"
  3. 点击"保存"
  **预期结果**：节点创建成功，在列表中可见
  ```

### 典型验收用例
- **数量**：5-15 个关键场景
- **覆盖**：正向流程、异常流程、边界情况
- **详细程度**：比研发自测用例更全面
- **格式**：
  ```markdown
  ## 典型验收用例
  
  ### 用例 1：正向流程 - 创建节点
  **前置条件**：用户已登录，拥有编辑权限
  **操作步骤**：...
  **预期结果**：...
  
  ### 用例 2：异常流程 - 重名节点
  **前置条件**：已存在名为"测试"的节点
  **操作步骤**：尝试创建同名节点
  **预期结果**：提示"节点名称已存在"，创建失败
  
  ### 用例 3：边界情况 - 节点名称长度
  **前置条件**：用户已登录
  **操作步骤**：输入 100 个字符的节点名称
  **预期结果**：提示"节点名称不能超过 50 字"
  ```

### 验收标准（调整为清单形式）
- **格式**：功能完整性、数据准确性、性能要求的清单
- **示例**：
  ```markdown
  ## 验收标准
  
  ### 功能完整性
  - [ ] 所有核心功能按流程可正常执行
  - [ ] 异常情况有明确提示
  - [ ] 权限控制按角色正确生效
  
  ### 数据准确性
  - [ ] 节点数据保存后可正确读取
  - [ ] 批量操作不丢失数据
  - [ ] 删除操作正确处理关联数据
  
  ### 性能要求
  - [ ] 列表页 2 秒内加载（100 条数据）
  - [ ] 批量导入 1000 条数据在 30 秒内完成
  ```

### 数据结构与兼容性
- **内容**：新增/修改的字段、兼容性考虑
- **格式**：
  ```markdown
  ## 数据结构与兼容性
  
  ### 新增字段
  - `node_status`（字符串）：节点状态，可选值 active/archived
  - `created_by`（用户 ID）：创建人
  
  ### 修改字段
  - `node_name`：长度限制从 100 调整为 50
  
  ### 兼容性考虑
  - 旧数据的 `node_status` 默认设为 active
  - 旧数据的 `created_by` 可为空
  ```

## 五不清单（核心边界）

见 `references/stage-rules.json` 的 `writingPrinciples.fiveNots`：
1. **不写技术实现**：不提及具体技术栈、架构模式、API 接口、代码片段、配置参数
2. **不写设计参数**：不定义色号、像素、字体，使用功能性描述
3. **不写 Skill/代码层内容**：不提及 Skill 名称或实现方式
4. **不写废话**：避免营销话术，多用要点和表格
5. **不设限**：不人为限制 PRD 结构的创造力

## 章节顺序参考

### CORE 阶段（10 个章节）
```
0. 元信息
1. 背景与问题
2. 产品目标与非目标
3. 目标用户与场景
4. 本期范围与明确不做
5. 核心用户流程
6. 功能概述
7. 非功能需求
8. 已确认决策
9. 待确认信息
```

### DETAILS 阶段（CORE 全部内容 + 10 个新章节）
```
（保留 CORE 全部章节）

10. 功能详细规则与状态
11. 角色和权限
12. 边界与异常处理
13. 研发自测用例
14. 典型验收用例
15. 验收标准
16. 上下游依赖
17. 数据结构与兼容性
18. 数据与效果验证
19. 发布前待办
```
