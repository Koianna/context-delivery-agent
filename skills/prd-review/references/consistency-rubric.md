# 一致性审查标准（6 个子维度）

> **配置文件**：审核维度定义在 `delivery-rules.json` 的 `reviewDimensions[5].subDimensions`

一致性是 PRD 质量的关键维度。新功能应与现有系统保持一致，降低用户学习成本和实现复杂度。

---

## 1. 术语一致性

**检查范围**：
- PRD 中使用的术语是否与术语表一致
- 同一概念在 PRD 中是否使用统一术语（避免同义词混用）
- 是否使用不在术语表中的新术语

**对照方法**：
- 参考 `context/01_产品Context/A_通用平台/01_产品认知/` 下的术语文件
- 首次出现缩写时需全称 + 缩写说明

**常见问题**：
- ❌ 使用同义词（如"组件" vs "元件"、"目标" vs "安全目标"）
- ❌ 使用缩写未说明（如 CS-GOAL、TS、DS）
- ❌ 术语定义与术语表不一致

**示例**：
```
✅ 正确：首次使用"网络安全目标（Cybersecurity Goal, CS-GOAL）"
❌ 错误：混用"组件"和"元件"指代同一概念
```

---

## 2. 交互模式一致性

**检查范围**：
- 新建/编辑/删除/批量操作/搜索/导出的交互是否与现有功能一致
- 确认对话框、操作反馈、错误提示的交互模式
- 空态、加载态、错误态的展示方式

**对照方法**：
- 参考同类功能的交互流程（如其他列表页的新建/编辑流程）
- 检查操作入口位置（工具栏 vs 右键菜单 vs 浮动按钮）

**常见问题**：
- ❌ 删除操作：其他功能需二次确认，新功能直接删除
- ❌ 搜索功能：其他功能实时搜索，新功能需点击"搜索"按钮
- ❌ 批量操作：其他功能用复选框，新功能用 Shift+点击

**示例**：
```
✅ 正确：删除攻击树节点需二次确认（与删除其他元素一致）
❌ 错误：删除攻击树节点直接删除（与现有模式不一致）
```

---

## 3. 信息架构一致性

**检查范围**：
- 新功能放在哪个菜单/模块下
- 层级深度是否与同级功能一致
- 页面标题/面包屑的命名规则

**对照方法**：
- 参考导航结构图或产品架构文档
- 检查同级功能的层级深度（一般不超过 3 层）

**常见问题**：
- ❌ 层级过深：首页 → 项目 → 建模 → 攻击树 → 节点管理 → 手动添加（5 层）
- ❌ 位置不合理：把"导出报告"放在"设置"菜单下
- ❌ 命名不一致：其他用"配置"，新功能用"设置"

**示例**：
```
✅ 正确：攻击树手动添加节点放在"建模 → 攻击树 → 添加节点"（3 层）
❌ 错误：放在"建模 → 攻击树 → 节点管理 → 手动添加"（4 层，过深）
```

---

## 4. 设计语言一致性

**检查范围**：
- 按钮文案、空状态、提示信息、时间/数字格式是否统一
- 成功/警告/错误的提示风格
- 图标使用、操作按钮位置

**对照方法**：
- 参考设计系统或 UI 组件库文档
- 检查同类操作的文案（如"保存" vs "确定"）

**常见问题**：
- ❌ 按钮文案：其他用"保存"，新功能用"确定"
- ❌ 空态文案：其他用"暂无数据"，新功能用"No Data"
- ❌ 时间格式：其他用"2026-08-27 10:00"，新功能用"08/27/2026 10:00 AM"

**示例**：
```
✅ 正确：空状态显示"暂无攻击树节点"+ 引导按钮"添加节点"
❌ 错误：空状态显示"No nodes available"（语言不一致）
```

---

## 5. 组件复用性

**检查范围**：
- 能复用现有组件的不新建（如列表、表单、对话框）
- 必须新建的考虑沉淀为通用组件
- 避免"换个皮"重复造轮子

**对照方法**：
- 参考 UI 组件库或已有页面
- 检查是否有相似功能已实现（如其他模块的"新建"对话框）

**常见问题**：
- ❌ 重复造轮子：自定义一个列表组件，而现有组件库有标准列表
- ❌ 不考虑复用：新建攻击树节点对话框与新建威胁场景对话框结构完全一样，但写了两套
- ❌ 过度定制：为一个特殊场景定制组件，导致其他地方无法复用

**示例**：
```
✅ 正确：新建节点对话框复用通用"表单对话框"组件
❌ 错误：为新建节点单独开发一个对话框组件（与其他新建对话框功能重复）
```

---

## 6. 业务规则一致性

**检查范围**：
- 权限控制、数据校验、状态流转、默认值的逻辑是否一致
- 异常处理、错误码、重试机制
- 审计日志、操作记录的记录规则

**对照方法**：
- 参考 `context/01_产品Context/B_TARA/` 下的业务规则文档
- 检查同类操作的权限控制规则

**常见问题**：
- ❌ 权限不一致：编辑攻击树需要"编辑"权限，编辑攻击路径只需"查看"权限
- ❌ 校验规则不一致：其他名称字段限制 50 字符，攻击树节点名称限制 100 字符（无业务理由）
- ❌ 状态流转不一致：其他对象删除后进入"已删除"状态，攻击树节点直接物理删除

**示例**：
```
✅ 正确：攻击树节点名称限制与其他元素名称限制一致（50 字符）
❌ 错误：攻击树节点名称限制 100 字符（无业务理由，不一致）
```

---

## 检查方法

### 主动对照

在写 PRD 前：
1. 检索 `context/01_产品Context/` 中相关模块文档
2. 查看同类功能的 PRD（如其他"新建"功能、其他"列表页"）
3. 识别可复用的交互模式、组件、业务规则

### 问题识别

审核 PRD 时，对每个不一致点追问：
- **为什么不一致？** 是业务需求驱动，还是无意为之？
- **不一致的代价是什么？** 用户困惑？实现复杂？维护成本？
- **能否统一？** 改新功能还是改旧功能？

### 严重级别判断

- **P0**：不一致会导致用户严重困惑或系统行为不可预测（如权限逻辑不一致）
- **P1**：不一致影响用户体验或增加实现成本（如交互模式不一致）
- **P2**：不一致是表达问题或局部优化空间（如按钮文案略有差异）

---

## 示例：完整一致性审查

**PRD 片段**：
```
## 功能需求
### 手动添加攻击树节点
- 用户点击"添加节点"按钮
- 弹出对话框，输入节点名称（最多 200 字符）
- 点击"OK"保存
- 保存成功后显示 Toast："Node added successfully"
```

**一致性审查结果**：

| 维度 | 问题 | 严重级别 |
|------|------|---------|
| 术语一致性 | ✅ 通过 | - |
| 交互模式一致性 | ✅ 通过（弹出对话框与现有模式一致） | - |
| 信息架构一致性 | ✅ 通过 | - |
| 设计语言一致性 | ❌ 按钮文案"OK"不一致（现有用"保存"）<br>❌ Toast 文案英文（现有用中文） | P1 |
| 组件复用性 | ✅ 通过（复用通用对话框） | - |
| 业务规则一致性 | ❌ 名称限制 200 字符不一致（其他元素 50 字符） | P1 |

**建议修复**：
```
- 按钮文案改为"保存"
- Toast 改为"节点已添加"
- 名称限制改为 50 字符（或说明为何需要 200 字符）
```
