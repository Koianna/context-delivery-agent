# Context Workspace

> 项目材料工作区 - 三层生命周期管理

## Directory Structure

| Directory | Purpose | Layer |
|-----------|---------|-------|
| `context/` | 已确认的知识 | 高可信度 |
| `workspace/` | 进行中的工作 | 中可信度 |
| `drafts/` | 正在形成的想法 | 低可信度 |

## Lifecycle

```
drafts/      → 原始材料、初步想法
  ↓ 人工确认
workspace/   → 正在进行的任务、PRD
  ↓ CP-C01 确认
context/     → 已验证的稳定知识
```

## Context 七层业务维度

`context/` 目录下按产品经理工作的 7 个核心维度组织稳定知识：

| 文件夹 | PM 工作里的含义 | 缺失后果 |
|--------|----------------|---------|
| `01_业务背景/` | 为什么现在要做 | AI 不知道任务优先级 |
| `02_用户场景/` | 谁在什么情况下遇到问题 | AI 容易写成抽象优化 |
| `03_产品现状/` | 当前系统怎么运转 | AI 提出脱离现状的方案 |
| `04_决策历史/` | 之前讨论过什么 | AI 重复旧方案 |
| `05_约束条件/` | 什么不能做或暂时做不了 | AI 写出不可落地方案 |
| `06_判断标准/` | 什么算好结果 | AI 不知道该优化什么 |
| `07_输出对象/` | 谁要看这份结果 | AI 抓错重点 |

**使用规则**：
- 这 7 个维度用于**手动整理**已确认的稳定知识
- Runtime 不会自动写入这些文件夹，由产品经理自行归纳
- 一份材料可能同时涉及多个维度，可在多个文件夹建立引用或复制关键信息
- 建议在文件开头用 Frontmatter 标注 `tags: [业务背景, 约束条件]` 标明跨维度属性

## Rules

- **不自动提升**：层级提升需要人工确认
- **When in doubt, drafts**：不确定时放 drafts
- **索引必须同步**：文件增删后更新索引
- **原文保留**：原始材料归档在 `.source-materials/`

## How to Use

- 当 AI 需要了解产品业务时 → 读 `context/`（优先查看 7 个维度文件夹）
- 当 AI 需要了解正在做什么时 → 读 `workspace/`
- 当提供新材料时 → 先放 `drafts/`，确认后提升
